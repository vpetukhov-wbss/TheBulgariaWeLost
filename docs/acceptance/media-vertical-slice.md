# Приемане на първия медиен вертикален срез

Този протокол доказва с изцяло синтетични файлове реалния поток Angular reverse proxy → NestJS → .NET Media → частно SFTP. Проверката не използва mock услуги и не записва пароли, access tokens или краткотрайни grants в резултата.

## Стартиране

От чист checkout с Docker и Docker Compose:

```sh
./scripts/dev-up.sh
```

Командата създава локалната среда, зарежда синтетичния профил и изпълнява `scripts/dev-media-acceptance.mjs`. Машинно четимият резултат е в игнорирания локален файл `.dev/media-vertical-slice-acceptance.json`.

## Приемателен сценарий

| Стъпка                       | Очакван резултат                                                                                                       |
| ---------------------------- | ---------------------------------------------------------------------------------------------------------------------- |
| Сесия за архивна PNG снимка  | NestJS записва предназначение, SHA-256, алтернативен текст, доказателство за права и първоначалния correlation ID      |
| Прекъснато качване           | Връзката се прекъсва след част от тялото; непълните байтове остават само в частната карантина                          |
| Повторение при активен lease | .NET връща публичния `409 media_conflict` за NestJS `upload_already_claimed`, със същия `X-Correlation-ID` и `traceId` |
| Възстановяване               | След изтичане на lease нов опит приема целия файл с `204`; старият опит не може да завърши записа                      |
| Проверка и преглед           | Worker проверява оригинала, публикува отделен preview и разрешеният `GET` и Range `GET` връщат правилните байтове      |
| Защита от replay             | Повторение след успешно completion връща `409`                                                                         |
| PDF източник                 | Валиден синтетичен PDF минава през същите реални приложения, inspection, preview и Range read                          |

## Проследими доказателства

`scripts/dev-check.sh` приема сценария само когато едновременно са изпълнени следните условия:

- SFTP съдържа четири нови обекта: оригинал и preview за PNG, оригинал и preview за PDF;
- карантината съдържа остатъка от нарочно прекъснатия опит;
- MongoDB съдържа точно двата очаквани `Completed` записа със `schemaVersion: 3`, completion attempt и съответния correlation ID;
- всеки HTTP отговор в сценария връща очаквания `X-Correlation-ID`, а Problem Details използва същата стойност в `traceId`;
- отчетът съдържа upload ID, correlation ID, SHA-256, MIME тип, права и резултат от всяка стъпка, но не съдържа удостоверителни данни.

Сценарият използва само еднопикселно синтетично PNG изображение и минимален синтетичен PDF. Истински архивни материали не трябва да се добавят към репото или CI fixtures.
